# Коммит

1. Посмотри `git status`, `git diff`, `git diff --staged` и `git log -5 --oneline`, чтобы понять изменения и принятый в репозитории стиль сообщений.
2. Проверь, что в коммит не попадут секреты (`.env`, ключи, токены), большие бинарные файлы и временные файлы. Если попадут — остановись и спроси.
3. Если изменения смешивают несколько несвязанных задач, предложи разбить их на несколько коммитов.
4. Добавь нужные файлы по именам (не `git add -A` вслепую).
5. Напиши сообщение в стиле репозитория: первая строка — что и зачем, до ~70 символов; при необходимости — пустая строка и пояснение «почему».
6. Создай коммит. Не используй `--no-verify` и `--amend`, не делай `push`, если пользователь об этом не просил.
7. Покажи хеш и первую строку коммита.
