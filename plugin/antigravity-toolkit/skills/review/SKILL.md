# Ревью изменений

1. Получи изменения: `git diff` и `git diff --staged`; для новых файлов — `git status`. Если пользователь назвал ветку или коммит, сравни с ним.
2. Для каждого изменённого места прочитай достаточно окружающего кода, чтобы понять поведение. Не ограничивайся строками диффа.
3. Ищи в первую очередь реальные ошибки: неверная логика, необработанные null/пустые значения, гонки, утечки ресурсов, сломанные вызовы в других местах, уязвимости (инъекции, секреты в коде). Стиль — только если мешает пониманию.
4. Каждую находку проверь: опиши конкретный сценарий, при котором она проявится. Без сценария — не включай.
5. Выведи список от самого серьёзного: `файл:строка` — проблема — сценарий — как исправить. Если проблем нет, так и скажи.
6. Ничего не исправляй без согласия пользователя.
